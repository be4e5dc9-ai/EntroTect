# 工具调用与压缩改进（2026-09-18）

对照本仓库 `agent-study` 笔记、其标注的本地源码，以及上游公开实现，解决当前执行器的具体问题。

| 参考实现 | 可借鉴的机制 | EntroTect 的落地 |
| --- | --- | --- |
| [DeepSeek Harness 调度器](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/src/tool-calls.ts) | 独占调用形成屏障，安全调用进入有界滚动池，结果按模型顺序提交 | 工具显式声明并发能力，默认独占；连续读取/搜索最多 8 路并行；写入、编辑和 Shell 串行；并行子代理单独分组，与主代理操作相互等待；取消时仍为未执行调用配对结果 |
| [本地 Claude Code 工具管线笔记](../agent-study/ClaudeCode/04-工具执行管线-并发编排与截断.md) | 执行前校验参数；单工具和整批结果分层控制体积 | 插件改写参数后先校验，再审批和执行；明确区分参数错误与执行失败；整批工具结果正文约 200KB 预算 |
| [OpenCode 输出管理](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/truncate.ts) | 大输出保留预览和完整文件，支持后续定位读取 | 以 UTF-8 字节控制预览，保留中文/emoji；允许 read 读取本会话的输出文件；窗口读取有后续行号，避免读取后再次无限落盘 |
| [本地 DeepSeek Harness 压缩与落盘笔记](../agent-study/deepseek-harness/07-上下文管理五层防线.md) | 日志落盘失败不改变原始操作的成功状态 | 写入或命令已完成时，落盘失败仅返回明确提示及有限预览，避免模型因误判失败而重复副作用 |

另修复 grep 结果使用应用启动目录而非会话目录计算相对路径，以及 read 提示窗口读取却始终拒绝大文件的问题。窗口读取流式计算完整文件指纹，后续编辑仍能识别可见行范围之外的外部修改。

压缩的摘要目标上限由 4,000 提高至 8,000 tokens；各档生成额度加倍，Max/Ultra 首次 65,536、长度截断重试最多 131,072 tokens。总超时由 3 分钟延至 5 分钟。输入总字符预算由 240,000 提至 480,000，单消息与工具证据额度也加倍。继续继承会话思考配置，并限制在模型已知输出上限和剩余上下文内；阈值仍为默认 70%。

这些是适合当前架构的针对性移植，不代表已实现参考项目的全部能力。独立子代理仍共享工作区，因此多个修改任务需要划分不重叠的文件范围；文件工具的新鲜度校验与锁继续生效。
