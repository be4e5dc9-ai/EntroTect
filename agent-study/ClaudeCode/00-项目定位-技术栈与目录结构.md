## 1. 项目定位

终端 AI coding agent。主循环把「system prompt + 历史 + 工具 schema」发给模型 → 模型流式返回 text/tool_use 块 → 本地执行工具 → tool_result 以 user 消息回填 → 再请求，直到模型不再调工具。

技术栈组合：

| 层 | 选型 |
|---|---|
| 运行时 | Bun（`package.json:18` `bun run src/dev-entry.ts`） |
| 语言 | TypeScript 全量 + Zod（schema 唯一事实来源） |
| 终端 UI | React + Ink（148 个组件） |
| 模型 API | Anthropic Messages API，**raw stream**（手写 SSE 解析） |
| 沙箱 | `@anthropic-ai/sandbox-runtime` OS 级沙箱 |

## 2. 入口链（从启动到主循环消费）

```
package.json:18            "dev": bun run src/dev-entry.ts
  └─ src/dev-entry.ts:145      转发到真正入口
      └─ src/entrypoints/cli.tsx:33   main()
          └─ cli.tsx:293           快路径分流后动态 import('../main.js')
              └─ cliMain()
                  ├─ 交互模式：src/screens/REPL.tsx:2825   ← React 组件消费主循环
                  ├─ 无头模式 -p：src/cli/print.ts         ← 单轮打印退出
                  └─ SDK 模式：src/QueryEngine.ts:184 class QueryEngine
```

**启示**：三种前端（交互 REPL / headless print / SDK QueryEngine）共享同一个 `query()` 主循环——UI 只是主循环的消费者。自研时先把 query() 写成纯库函数，再套 UI。

## 4. 组织方式的可借鉴点

1. **一个工具一个目录**：实现 + 给模型的 prompt 文本 + UI 渲染 + 权限校验四件套内聚，新增工具零散落。
2. **services 层按"横切关注点"切**：api / tools / compact 三条线各自有独立的编排文件，主循环只做调度。
3. **constants 集中魔法数字**：截断上限、提示词分界符、工具名单全部收口在 constants，改行为不用翻业务代码。
4. **feature-gate 目录化**：实验特性（coordinator、proactive 等）整目录隔离，用 env 开关装载。
