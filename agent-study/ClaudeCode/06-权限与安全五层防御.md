# Claude Code 权限与安全机制（五层纵深防御）

> 归属：`agent-study/ClaudeCode/` | 关键词：PermissionMode、allow/deny/ask、规则匹配、Bash 安全、yoloClassifier、沙箱、hooks
> 核心文件：`src/types/permissions.ts`、`src/utils/permissions/`、`src/tools/BashTool/`、`src/types/hooks.ts`

---

## 总览：五层防御

```
第1层 模式与决策模型 → 第2层 规则体系 → 第3层 Bash 专用安全子系统
     → 第4层 auto-mode LLM 分类器 → 第5层 OS 沙箱 + Hooks 协议
```

## 第 1 层：模式与决策模型（types/permissions.ts）

- **mode** ∈ `acceptEdits | bypassPermissions | default | dontAsk | plan`（+内部 auto）
- **behavior** 三态：`'allow' | 'deny' | 'ask'`
- **决策三类**：

```ts
PermissionAllowDecision { updatedInput?, acceptFeedback? }   // 可改写参数后放行
AskDecision             { message, suggestions?: PermissionUpdate[] }
                        // ★ suggestions 是"总是允许"按钮的数据协议：
                        //   UI 一键把规则写入 settings
DenyDecision            { message }
// 另有 passthrough 变体（工具自己不决定，交上层）
```

- **DecisionReason** 11 种：rule / mode / hook / classifier / sandboxOverride / safetyCheck…——每个决定都可解释。

## 第 2 层：规则体系

- 规则形状：`{ toolName, ruleContent? }`，如 `Bash(git *)`、`Read(./docs/**)`。
- 来源八种（优先级不同）：userSettings / projectSettings / localSettings / flagSettings / policySettings / cliArg / command / session。
- **deny 规则在工具池组装时就过滤掉工具本身**（tools.ts:262-269）——被禁工具根本不出现在发给模型的 tools 列表里，模型连尝试的机会都没有。
- 运行时统一签名 `CanUseToolFn`（hooks/useCanUseTool.tsx:27），三种实现可插拔：交互 UI 对话框 / SDK 结构化 IO / Bridge 远程审批。

## 第 3 层：Bash 专用安全子系统（tools/BashTool/）

| 机制 | 说明 |
|---|---|
| 危险模式识别 | rm -rf /、fork bomb、管道提权等模式库 |
| **wrapper 剥离** | 规则匹配前剥掉 `timeout / nohup / nice` 与环境变量前缀（含 GNU flag 注入防护）——`timeout 10 npm install` 也能命中 `Bash(npm install:*)` 规则 |
| argv 级路径边界校验 | 解析命令里出现的路径是否越出工作区 |
| sed -i 模拟编辑 | `sed -i` 先解析成预览 diff 走审批；批准后权限系统注入 `_simulatedSedEdit` 字段执行。该字段在模型 schema 中 omit + 执行前再剥离，双保险 |

## 第 4 层：auto-mode LLM 分类器（yoloClassifier.ts）

- 两阶段 XML 输出（fast → thinking），判定命令风险；
- 与 hooks **并行投机启动**，不增加串行延迟；
- 连续拒绝计数达阈值自动退回人工询问（防分类器被绕过）；
- PermissionDenied hook 可返回 `{retry:true}` 放行。

## 第 5 层：OS 沙箱 + Hooks 协议

- 命令默认可进 OS 级沙箱（`@anthropic-ai/sandbox-runtime`，适配层 `utils/sandbox/sandbox-adapter.ts`）；
- 逃逸需用户批准 `dangerouslyDisableSandbox` 参数（在模型可见 schema 中声明，本身就是一次显式审批）；
- **Hooks 协议**（types/hooks.ts:50-166）：PreToolUse（可直接 allow/deny + updatedInput）、PostToolUse、PermissionRequest、UserPromptSubmit、Stop、PreCompact 全生命周期覆盖。

## 核心原则：deny 要回喂理由

拒绝不是终点——把拒绝原因作为 is_error 结果回喂，模型会换一条路（比如改用用户允许的方式）。静默失败只会让模型反复重试同一动作。

## 自研最小实现清单

1. behavior 三态 + 每工具 checkPermissions + 一个交互对话框；
2. 通配符规则 `Tool(pattern)` + wrapper 剥离后匹配；
3. deny 回喂理由；
4. （进阶）LLM 分类器 + OS 沙箱。
