# Claude Code 上下文管理：六层压缩栈

> 归属：`agent-study/ClaudeCode/` | 关键词：autocompact、microcompact、snip、contextCollapse、reactiveCompact、阈值公式
> 核心文件：`src/services/compact/`（autoCompact / compact / microCompact / reactiveCompact / snipCompact / contextCollapse）

---

## 1. 六层栈总览（每轮循环按序执行，调用点见主循环文档）

| 层 | 位置 | 做法 | 成本 |
|---|---|---|---|
| 工具结果预算 | `toolResultStorage.ts:924` | 单消息 >200k 字符，最大块换落盘预览 | 零模型调用 |
| Snip | `snipCompact.ts` | HISTORY_SNIP 门控强制截断 | 零 |
| Microcompact | `microCompact.ts:253` | 只清老 tool_result 内容留结构骨架；cached 变体用 **cache-editing API 删远端缓存**，不打爆本地前缀 | 零 |
| ContextCollapse | `contextCollapse/` | 分段归档投影；413 时先排水 | 零 |
| Autocompact | `autoCompact.ts:241` → `compact.ts:387` | forked agent 全量摘要替换历史 | 一次 LLM 调用 |
| Reactive compact | `reactiveCompact.ts` + `query.ts:1119` | 收到真实 413 后被动兜底全量摘要 | 一次 |

设计逻辑：**按成本递增的阶梯**——能用零成本手段解决就不动用 LLM 摘要。

## 2. 阈值公式（可直接抄）

```ts
// autoCompact.ts:33
getEffectiveContextWindowSize = contextWindow(model) − min(maxOutputTokens, 20_000)
// :72
getAutoCompactThreshold       = effective − 13_000        // 提前量
// utils/tokens.ts:44 —— 占用计算包含缓存四项：
contextTokens = input + cache_creation + cache_read + output
```

- 关闭 autocompact 时：硬阻塞线 = effective − 3k，直接终止回合提示手动 /compact（`query.ts:628`）；
- **熔断**：autocompact 连续失败 ≤3 次，之后不再尝试（`:70`），防止反复摘要烧钱。

## 3. 全量摘要流程 compactConversation（compact.ts:387）

```
PreCompact hooks
→ forked agent 发独立摘要请求（不占主上下文）
   prompt 要求：<analysis> 草稿 + 九段式 <summary>
   （原任务 / 技术要点 / 文件编辑 / 错误修复 / 所有用户消息 / 未完成任务 / 续作上下文…）
→ 自身也 413？→ 按 API round 截头重试
→ 成功后状态重建：
   - 清空 readFileState（文件新鲜度缓存全部失效）
   - 恢复最近 ≤5 个已读文件附件（单个≤5k token / 总 50k）
   - 重注 plan / skill / plan-mode 附件
→ 续接模板注入："This session is being continued from a previous conversation…"
   + 原 transcript 路径（模型可自行回读）
```

## 4. Microcompact 的 cache-editing 技巧

普通做法删本地消息会改变前缀、打爆 prompt cache。cached 变体使用 provider 的 **cache-editing API 直接删除远端缓存中的旧 tool_result 内容**——本地前缀字节不动，远端缓存瘦身。

## 5. 自研启示

1. 最小可用 = 一层 autocompact（阈值触发 + forked agent 摘要 + 续接模板）。
2. 阈值公式三件套：effective = window − min(maxOut, 20k)；threshold = effective − 13k；占用含 cache 四项。
3. 摘要 prompt 必须要求保留"所有用户消息 + 未完成任务"，否则续接后丢目标。
4. 压缩后必须重建文件读取状态缓存（否则 Edit 的"先读后改"校验会误报）。
