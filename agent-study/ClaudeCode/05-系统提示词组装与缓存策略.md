# Claude Code 系统提示词组装与 prompt cache 策略

> 归属：`agent-study/ClaudeCode/` | 关键词：getSystemPrompt、DYNAMIC_BOUNDARY、env 块、cache_control、prependUserContext
> 核心文件：`src/constants/prompts.ts`、`src/context.ts`

---

## 1. 两段式结构

### 1.1 静态段（可跨用户 global cache）

`getSystemPrompt()`（prompts.ts:444-577）返回分段数组（`:560-571`）：

| 段 | 内容要点 |
|---|---|
| 身份 intro | 含网络安全指令 |
| `# System` | 输出即展示、权限说明、system-reminder 标签语义、提示注入警示 |
| `# Doing tasks` | 不过度设计、先读后改、反谄媚条款 |
| `# Executing actions with care` | **可逆性/爆炸半径原则**——危险操作前评估后果 |
| `# Using your tools` | 专用工具优先于 Bash、并行调用指引 |
| Tone & 输出效率 | 简洁回答 |

### 1.2 分界符

```ts
// prompts.ts:114
export const SYSTEM_PROMPT_DYNAMIC_BOUNDARY = '__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__'
```

边界**之前**打 `scope:'global'` 缓存断点（所有用户共享的稳定前缀）；边界之后是会话私有动态内容。

### 1.3 动态段（registry 管理，`:491-555`）

| 动态块 | 内容 |
|---|---|
| session_guidance | 按当前启用的工具条件拼装的使用指引 |
| memory | memory 目录说明 |
| env_info_simple | `computeSimpleEnvInfo :651-710`：<env> 块 = cwd / git worktree / platform / shell / OS 版本 / model / knowledge cutoff |
| language | 用户语言偏好 |
| output_style | 输出风格开关 |
| mcp_instructions | MCP 使用说明——**标记 uncached，因为 MCP server 会中途连断** |
| scratchpad / FRC / token_budget | 草稿区、频率控制、token 预算告知 |

## 2. 运行时上下文第二通道（保 cache 的关键技巧）

gitStatus 和 CLAUDE.md 这类每回合都可能变的内容**不进 system prompt**，而是走 user 消息通道：

```
src/context.ts:
  getSystemContext :116   → gitStatus（branch / status 截 2000 字符 / recent commits，:61-103）
  getUserContext   :155   → CLAUDE.md 内容 + 当前日期

主循环拼接：
  system 侧: appendSystemContext(query.ts:449)      → 追加到动态段末尾
  user   侧: prependUserContext(query.ts:660)       → 作为首条 user 消息的前缀 ★
```

API 层再包一层 attribution 头 + CLI prefix（claude.ts:1358-1369），最后由 `buildSystemPromptBlocks :1376` 统一打 cache_control 断点。

**为什么**：system 前缀字节级稳定才能吃满 provider 的 KV/prompt cache；易变的 env 信息放 user 通道，缓存失效只影响便宜的前缀外部分。

## 3. 子代理轻量路径

子代理不用完整提示词：

```ts
enhanceSystemPromptWithEnvDetails :760   // 绝对路径要求 / 无 emoji / envInfo 注入
DEFAULT_AGENT_PROMPT :758                // 一句话身份
```

## 4. 自研启示

1. 提示词 = 静态规范（global cache）+ 分界符 + 动态注册表（session）三层。
2. 易变信息走首条 user 消息前缀，不动 system。
3. 提示词内容本身要教模型"如何用工具"（专用工具优先于 Bash、并行指引），这是行为质量的杠杆点。
