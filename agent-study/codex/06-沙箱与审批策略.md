## 1. 平台差异统一抽象（sandboxing/src/manager.rs:37-76）

```rust
pub enum SandboxType { None, MacosSeatbelt, LinuxSeccomp, WindowsRestrictedToken }

pub fn get_platform_sandbox(windows_sandbox_enabled: bool) -> Option<SandboxType> {
    if cfg!(target_os = "macos") { Some(SandboxType::MacosSeatbelt) }
    else if cfg!(target_os = "linux") { Some(SandboxType::LinuxSeccomp) }
    else if cfg!(target_os = "windows") {
        if windows_sandbox_enabled { Some(SandboxType::WindowsRestrictedToken) } else { None }
    } else { None }
}
```

统一管线：SandboxManager::transform(SandboxTransformRequest)（manager.rs:131-145）把 SandboxCommand { program, args, cwd, env } 改写成平台特定 argv。

## 2. 各平台实现要点

| 平台 | 机制 |
|---|---|
| **macOS Seatbelt** | 强制只用绝对路径 /usr/bin/sandbox-exec（56 行，防 PATH 注入）；SBPL profile 由三段 include_str! 模板拼装（21-27：base/network/preferences + 受限只读平台默认），再叠加工作区可写目录、代理环回端口放行、Unix socket 白名单等规则，生成 (deny default) 式策略 |
| **Linux** | landlock.rs:23-60 生成 `codex-linux-sandbox --sandbox-policy-cwd <p> --command-cwd <p> --permission-profile <json> [--use-legacy-landlock] [--allow-network-for-proxy] -- <command>`。助手默认 **bubblewrap**：--ro-bind / / 只读基线 + 可写根 --bind + 保护子路径 .git/.codex 重挂只读 + --unshare-user/pid/net + seccomp 网络过滤 + PR_SET_NO_NEW_PRIVS；托管代理模式用 TCP→UDS→TCP 桥并封死 AF_UNIX。features.use_legacy_landlock=true 回退内核 Landlock。WSL1 因无法建 user namespace 直接拒绝 |
| **Windows** | windows-sandbox-rs 受限令牌沙箱（AppContainer 风格）；core/src/windows_sandbox.rs 管理 WindowsSandboxLevel、私有桌面、提升/非提升后端选择 |

违规审计：violation.rs 提供 record_filesystem_sandbox_violation / record_network_sandbox_violation——把 Seatbelt/Landlock 日志解析成 SandboxViolationEvent **反馈给模型**（"你越权了，原因是…"）。

## 3. 审批策略枚举（protocol.rs:906-986）

```rust
#[serde(rename_all = "kebab-case")]
pub enum AskForApproval {
    UnlessTrusted,                    // untrusted：非白名单命令一律询问
    #[default] OnRequest,             // on-request：模型自行决定何时求助
    Granular(GranularApprovalConfig), // granular：按类别开关（sandbox_approval/rules/
                                      //   skill_approval/request_permissions/mcp_elicitations）
    Never,                            // never：永不打扰，失败直接回给模型
}

#[serde(tag = "type", rename_all = "kebab-case")]
pub enum SandboxPolicy {
    DangerFullAccess,
    ReadOnly { network_access: bool },
    ExternalSandbox { network_access: NetworkAccess },   // 已处于外部沙箱
    WorkspaceWrite { writable_roots: Vec<AbsolutePathBuf>, network_access: bool,
                     exclude_tmpdir_env_var: bool, exclude_slash_tmp: bool },
}
```

WritableRoot（1066-1076）：可写根下自动保护 `.codex`、`.git`（尤其 `.git/hooks`）等可提权元数据路径（is_path_writable 1079-1097）。

用户决定枚举 ReviewDecision（3877-3915）：Approved / ApprovedExecpolicyAmendment{prefix} / ApprovedForSession / ApprovedMcpPolicyAmendment / NetworkPolicyAmendment{host,action} / Denied{rejection} / TimedOut / Abort。

## 4. 审批数据流与编排器

ExecApprovalRequestEvent（approvals.rs:225-291）携带：call_id/approval_id、command、cwd、reason、network_approval_context、proposed_execpolicy_amendment、proposed_network_policy_amendments、additional_permissions，以及**服务端建议的按钮集合 available_decisions**（缺省推导 300-347）。客户端弹窗后发送 Op::ExecApproval，handlers.rs:174 将决定投递给挂起的审批 future。

编排器注释即总结（core/src/tools/orchestrator.rs:1-8）：

> Central place for approvals + sandbox selection + retry semantics. Drives: approval → select sandbox → attempt → retry with an escalated sandbox strategy on denial (no re-approval thanks to caching).

即：先按 default_exec_approval_requirement(approval_policy, fs_policy) 判定是否需要询问（tools/sandboxing.rs）；被拒后可换更高权限档位重试一次而不再重复打扰（审批缓存）。

另有：
- **Guardian 自动审批审查器**（ext/guardian-v2）：LLM 评审危险操作，评估事件/风险级别定义在 approvals.rs:104-223;
- **execpolicy**：Starlark 写成的命令前缀规则（.rules），允许/prompt/拒绝三态（execpolicy/，docs/execpolicy.md）。

## 5. 自研最小实现

1. 三态审批起步：Untrusted/OnRequest/Never；
2. Linux 用 bwrap 一条命令包住：`--ro-bind / / --bind $PWD $PWD --unshare-net --`；macOS 用 sandbox-exec SBPL；Windows 可先 DangerFullAccess 占位；
3. 被拒后升级重试要带审批缓存，避免重复打扰。
