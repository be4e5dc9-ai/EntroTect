# Codex 从零复刻最小路径（7 步）

> 归属：`agent-study/codex/` | 关键词：最小可行 Rust agent、实施顺序
> 预估：约 10-14 人日可得"单模型、单机、shell+patch 双工具、可断点续跑"的最小 coding agent

---

## 第 1 步：定义协议（半天）

新建 protocol 层，写三个枚举（照抄 protocol/src/models.rs:938-1100 的精简版）：

- `ResponseItem`：Message / Reasoning / FunctionCall / FunctionCallOutput / CustomToolCall;
- `Op { Interrupt, UserTurn{input}, ExecApproval{id,decision}, Shutdown }`;
- `EventMsg { TurnStarted, TurnComplete, AgentMessage, AgentMessageDelta, ExecCommandBegin/End, ExecApprovalRequest, Error, TokenCount }`.

加 `Submission{id, op}` 与 `Event{id, msg}` 信封。这一层不依赖任何其他东西。

## 第 2 步：模型客户端（1 天）

实现 Responses API SSE 调用：

```
POST /v1/responses  { model, instructions, input, tools, stream: true }
```

把 SSE 事件映射为自己的 ResponseEvent（照抄 codex-api/src/common.rs:76-123 子集 + map_response_events 思路）。对外暴露 `fn stream(Prompt) -> impl Stream<Item=Result<ResponseEvent>>`，Prompt { input: Vec<ResponseItem>, tools, base_instructions }（client_common.rs:19）。

## 第 3 步：工具执行器（2 天）

- 定义 ToolSpec::Function{name, description, parameters} + create_tools_json()（tool_spec.rs）；
- 实现 exec_command 工具：shell_spec.rs:21 的 schema + std::process/pty 执行 + format_exec_output_for_model() 的 "Exit code:/Wall time:/Output:" 文本格式（tools/mod.rs:93-118）;
- 实现 apply_patch：先写 parser（parser.rs 文法 + Hunk/UpdateFileChunk），再做"验证后应用"（lib.rs verify → apply_hunks_to_files），seek_sequence 容忍上下文漂移。

## 第 4 步：主循环（2 天）

Session + 两个 channel（SQ 有界/EQ 无界）+ submission_loop（handlers.rs:515 精简版）+ run_turn 主循环骨架：

```text
loop {
    input = history.for_prompt();
    stream(model(input, tools));
    for item in stream { persist(item); if tool_call { outputs.push(execute(item)) } }
    history += outputs;                  // 工具输出回灌
    if outputs.is_empty() { break };     // 无新工具调用 → turn 结束
}
```

加上：needs_follow_up 判定、end_turn:false 处理、错误转 FunctionCallOutput 回流。

## 第 5 步：审批 + 沙箱（3-5 天，可裁剪）

- AskForApproval::{Untrusted, OnRequest, Never} 三态起步；需要执行的命令先问一次（emit ExecApprovalRequest，等待 Op）；
- Linux 用 bwrap 一条命令包住：`--ro-bind / / --bind $PWD $PWD --unshare-net --`；macOS 用 sandbox-exec SBPL；Windows 可先用 DangerFullAccess 占位。

## 第 6 步：持久化 + resume（1 天）

JSONL append-only：首行 SessionMeta，此后每行 {timestamp, ordinal, item}（RolloutLine）；resume = 读全量 → 重建 Vec\<ResponseItem\> → 继续追加。压缩最后做：超阈值把历史喂给模型求摘要、替换历史并存 Compacted 检查点。

## 第 7 步：外壳（各 1 天）

- headless：codex exec "prompt" → 打印 AgentMessage；--json 时输出 ThreadEvent JSONL;
- TUI：任何能画流式文本的前端即可——只要它说第 1 步的协议。这正是 Codex 把 TUI 也做成协议客户端的动机。

## 收尾认知

之后再按需引入 MCP 客户端（rmcp）、多环境、子代理、Guardian 自动审批、code-mode 等高级特性——这些在本仓库中都严格做成了**可选层而不是侵入主循环**。"核心极简 + 特性外挂"的分层本身就是最值得学习的架构决策。
