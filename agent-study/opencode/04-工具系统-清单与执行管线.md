## 3. 动态描述注入

describeTask（registry.ts:265-278）：把所有非 primary 且未被 task 权限 deny 的 agent 渲染成清单拼进 task 工具 description——**工具描述本身是运行时计算出来的**。每个工具定义还会经 `plugin.trigger("tool.definition")` 让插件改写（318 行）。

## 4. 工具执行管线

```
LLM 流事件 tool-call(id, name, input)
→ processor.ensureToolCall: 建 ToolPart(pending→running) 并持久化     processor.ts:216-253
→ AI SDK 内部调用 tool().execute(args, options)                       session/tools.ts:99-133
    ├─ EffectBridge.run.promise(...) 提升 Effect 为 Promise            tools.ts:103
    ├─ plugin.trigger("tool.execute.before")                          :106-110
    ├─ item.execute(decodedArgs, ctx)   ← Tool.define 包装：
    │     Schema 解码校验 → InvalidArgumentsError(可自愈)               tool.ts:111-129
    │     执行 → ExecuteResult{title, metadata, output, attachments}
    │     ctx.metadata() 运行中多次回调 → 更新 ToolPart.state.metadata
    │       （UI 实时看到进度，如 bash 输出预览）
    │     Truncate.output 截断 + outputPath                           tool.ts:131-144
    └─ plugin.trigger("tool.execute.after")                           tools.ts:121-125
→ AI SDK 发出 tool-result 事件
→ processor.completeToolCall: ToolPart → completed 持久化
    + 发布 message.part.updated                                       processor.ts:160-184
→ 权限拒绝时 failToolCall → status:"error"
    用户拒绝且未开 experimental.continue_loop_on_deny 则整轮停止        processor.ts:186-205
```

关键点：

- **权限内嵌于 ctx**：context() 把 ask 绑定为 `Permission.ask({ruleset: merge(agent.permission, session.permission)})`（tools.ts:81-89）；工具实现里显式 `yield* ctx.ask({permission, patterns, always, metadata})`；
- MCP 工具执行前统一 `ctx.ask({permission:<工具名>, patterns:["*"], always:["*"]})`——默认每次询问，allow 后永久记忆。

## 5. 自研启示

1. invalid 兜底工具 + repairToolCall（小写修复→否则重定向 invalid 回喂错误）是参数自愈的标准组合。
2. "工具描述运行时计算"让权限/子代理状态自动反映到模型视野。
3. 执行管线的 before/after 钩子对是所有横切能力（审计、脱敏、指标）的挂点。
