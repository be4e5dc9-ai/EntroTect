## 1. 触发条件：overflow 计算（overflow.ts）

```ts
const COMPACTION_BUFFER = 20_000
// :10-20
usable   = model.limit.input ? input − reserved : context − maxOutputTokens
reserved = cfg.compaction.reserved ?? min(20k, maxOutputTokens(model))
// :22-34
isOverflow = !(compaction.auto === false) &&
             (tokens.total || input+output+cacheRead+cacheWrite) >= usable
```

两个触发点：
1. 主循环里上一条 assistant 的 tokens 超限（prompt.ts:1161-1168）；
2. 流处理中 provider 直接报 ContextOverflowError（processor.ts:607-618，halt 分支置 needsCompaction=true）。

## 2. 压缩执行：哨兵消息 + 异步处理两阶段 ★

### 阶段一 create()（compaction.ts:559-582）

只插入一条带 CompactionPart 的 user 消息就返回——主循环下一轮检测到该 task 再同步处理。保证压缩本身可被追踪、可恢复。

### 阶段二 processCompaction()（319-557）

1. **select 选保留尾巴**：历史按 user 消息切成 turns；预算 `preserve_recent_tokens = clamp(usable×25%, 2k..15k)`（115-120）；从最近 turn 往回累加 token 估算直到预算耗尽；splitTurn 甚至能在单个 turn 内按消息粒度再细分（140-163）；
2. **折叠历史压缩**：找出之前已完成的 (CompactionPart user, summary assistant) 对，从本次输入剔除并取出上次摘要作 previousSummary——**滚动摘要递增更新**（97-113）;
3. **serialize 渲染 head 为紧凑文本**（54-85）：`[User]: …`、`[Assistant]: …`、`[Assistant tool call]: name(input)`、`[Tool result]: …`（工具输出单条截 2000 字符）;
4. 用隐藏的 **compaction agent**（permissions `"*":"deny"` 无任何工具、专用 prompt `agent/prompt/compaction.txt`）跑一轮 LLM；
5. 成功后记录 tail_start_id、发布 compaction.compacted 事件；自动续跑时插入合成 user 消息 *"Continue if you have next steps…"*（metadata.compaction_continue 标记，可被插件钩子关停，468-549）；overflow 场景把触发溢出的原始 user 消息在新上下文里重放（媒体降级为文字占位，340-356、469-495）。

filterCompacted（message-v2.ts:521-576）在每次取历史时把 `[压缩user, summary, 保留tail, 后续…]` 重排出模型视角的时间线。

## 3. prune()：独立于压缩的工具输出清理

```
倒序累计已完成工具输出的 token
超过 PRUNE_PROTECT = 40k 的旧输出就地抹除
  （state.time.compacted 时间戳标记 → 重放显示 "[Old tool result content cleared]"）
仅当可回收 > PRUNE_MINIMUM = 20k 才动手
skill 工具输出受保护
主循环结束后 fork 执行 (prompt.ts:1338)
```

step-finish 事件携带 usage + providerMetadata → Session.getUsage 计算 tokens/cost 写入 Assistant.tokens 与 StepFinishPart（processor.ts:435-484）。

## 5. V2：Context Epoch 与安全边界（前瞻设计）

系统提示词重构为**可独立刷新的类型化事实源**：

```ts
// core/system-context/index.ts
interface Source<A> {
  readonly key: Key                                   // 稳定命名空间键，如 "env/date"
  readonly codec: Schema.Codec<A, Json>
  readonly load: Effect<A | Unavailable>
  readonly baseline: (current: A) => string           // 首次渲染
  readonly update: (previous: A, current: A) => string // 变更增量文案
  readonly removed?: (previous: A) => string           // 移除文案
}
```

机制：
- initialize 产出不可变 **Baseline System Context** + 结构化 Snapshot（存 session_context_epoch 表 sql.ts:168-176）；baseline 在整个 Epoch 内**逐字复用以命中 provider prompt-cache**（runner 还发送 x-session-affinity 头和 OpenAI promptCacheKey，runner/llm.ts:204-214）；
- 每个 provider turn 前 reconcile(snapshot)：变化的事实**不在发生时就推送**，而是在下一个 Safe Provider-Turn Boundary 合并成一条持久的 Mid-Conversation System Message（CONTEXT.md:93-98）;
- 观察失败遵循 stale-while-revalidate，绝不构造残缺 baseline（198-206 返回 InitializationBlocked）;
- 内置源：环境事实、日期、全局/向上发现的 AGENTS.md 聚合、所选 agent 的 skill 清单（168-171）;
- 压缩完成 ⇒ 新 Epoch；移动 session ⇒ 清 Epoch。

## 6. 自研启示

1. 最小可用压缩 = overflow 公式 + serialize 滚动摘要（[User]/[Assistant]/[Tool result] 格式）+ 保留尾巴预算 clamp(usable×25%, 2k..15k)。
2. 压缩做成哨兵消息两阶段，可恢复可追踪。
3. prune 与压缩是两条独立防线：前者零模型调用清老工具输出。
