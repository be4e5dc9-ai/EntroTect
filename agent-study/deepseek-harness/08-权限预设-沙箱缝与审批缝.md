# DeepSeek Harness 权限预设、沙箱缝与审批缝

> 归属：`agent-study/deepseek-harness/` | 关键词：permission-presets、SandboxMode、confine、ConfinedArgv、fail-closed、Seatbelt、bubblewrap、ACL
> 核心文件：`packages/sandbox/sandbox/src/index.ts`、`packages/interaction/user-approval/`、`packages/bundle/base/cordis.patch.yml`

---

## 1. 权限 = 沙箱 × 审批两个正交旋钮

三档用户可见预设（base yml L193-206）：

```yaml
presets:
  read-only:          { sandbox: read-only,          approval: ask   }
  workspace-write:    { sandbox: workspace-write,    approval: ask   }   # 默认
  danger-full-access: { sandbox: danger-full-access, approval: never }
```

## 2. 沙箱缝（sandbox/src/index.ts）

文件效果三模式：`SandboxMode = 'read-only' | 'workspace-write' | 'danger-full-access'`（L29）。

核心抽象极小（L158-176）：

```ts
abstract confine(argv: readonly string[], policy: SandboxPolicy): ConfinedArgv
```

设计要点：

| 要点 | 说明 |
|---|---|
| 策略逐调用携带 | 不固定在 provider 上——同一瞬间 bash 可 read-only 跑，受限 child agent 同时需要可写状态目录；批准后的升级重试就是更宽策略的新调用（L62-68） |
| ConfinedArgv 返回值 | `{ argv(包装后的替代命令), enforcement: 'full'\|'partial', denialSignatures(该后端的拒绝"方言"), runnerFailureRules }`（L95-116）——消费者据 stderr 区分"沙箱拦住了（策略生效）"vs"runner 自己坏了（命令没跑）" |
| **Fail-closed** | 无可用后端抛 SandboxUnavailableError（code SANDBOX_UNAVAILABLE，L124-144）；"silent unconfined passthrough is forbidden"（L154） |

后端矩阵（sandbox-local）：Linux bubblewrap / npm 分发的 landlock-run（native/landlock-run 原生源码）、macOS Seatbelt(sandbox-exec)、Windows ACL 受限令牌（capability-SID 写白名单，sandbox-windows-acl）；功能探测仲裁多 runner 链。**E2B 包演示同一套 fs/subprocess 缝换成远程微 VM 后 Bash/PTY/LSP 整链迁移**（architecture.md L100-102）——缝的价值证明。

## 3. 审批缝（interaction/user-approval）

fail-closed 的一次性许可决定。接入点即工具管线第③段 serviceAsk：

```
ask 决策 → ctx.get('approval') 审批缝裁决
  无审批缝 / 无 agent        → 降级 deny
  allowed-once / rejected /
  cancelled / unavailable    → 四种结果映射成不同 deny 理由
                              "让模型能区分人的'不行'和审批通道缺失"(L1713-1715 注释)
danger-full-access 预设       → approval 直接 never
```

## 4. 纵深防御实例

| 组件 | 机制 |
|---|---|
| bash-sandbox | 每条命令经 ctx.sandbox 包装；被拦截时结果报告 `[sandbox: file access denied under <mode> mode]`——模型可见文案明示"这是策略拒绝不是 bug，别换姿势重试" |
| fs-sandbox | 按逐调用模式围栏 write/edit |
| repeat-tool-reminder | 相同调用重复 [3,5,8] 次时注入提醒（防死循环） |
| tool-call-timeout-policy | 以 tools/execute 包装器实现 per-tool 截止时间 |

## 5. 自研最小实现

1. `confine(argv, policy) -> argv'` 接一个平台后端即可起步（macOS sandbox-exec 或 Linux bwrap 最简单）；
2. 无后端时 fail-closed 报错而非放行；
3. 拒绝信息回喂模型并注明是策略拒绝。
