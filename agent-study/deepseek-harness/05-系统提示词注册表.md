## 2. 组装流程 assemble()（L467-542）

```
合并全局+scope 链的 variables（近者胜）
→ sections 遮蔽排序
→ 收集所有 tool provider 的 schema（structuredClone 解耦，防止共享可变引用）
→ orderTools 应用部署级 toolOrder 配置
   （必须恰好含一个 <unlisted-tools> rest 占位符 L139-157；未配置则字典序）
→ 发 system-prompt/assemble waterfall（返回值权威，插件最后改写机会）
→ complete 段恢复为唯一 section
```

## 3. 动态上下文 = 持久化的 user 消息快照 ★

PromptContext 不是每次塞 system，而是渲染成一条 **user-role 快照**追加进对话：

> 前缀原文（joinContextSections L236-240）：*"Current runtime context. This snapshot supersedes earlier runtime-context snapshots."*

RuntimeContextProjection（runtime-context.ts）负责去重：
- 只在内容变化时生成新快照；
- 旧快照被 compaction replace 阴影后置 null；
- 清空时写固定清除语。

满足仓库最高不变量 **"Model-visible ⟺ logged"**（architecture.md L96）：任何到达模型请求的东西必须能从日志重建。

## 4. AGENTS.md 工作区指令注入

- 基线指令在**第一个请求之前**作为持久 user 消息注入；
- 当 fs 工具触碰文件（FILE_TOUCH_TOOL_NAMES = read/write/edit，L70）时，从该路径向上发现嵌套的/变更的/删除的 AGENTS.md，通过 `agent.inject()` 投影进 inbox（touch 追踪 + 投影尾队列 L72-103）；
- 预算控制：maxBytes 65536（bundle/base/cordis.patch.yml:232-235）。

这就是"仓库级指令文件如何进入 agent"的完整机制——按需发现而非启动时全量扫描。

## 5. Persona 作为组合行

preset/persona：deployment persona 由 system-prompt config 全局持有；agent preset 无法挂载 prompt registry 本身，于是提供 scope-only 行——在 agent 作用域内注册同名 `deployment:persona` 段实现遮蔽（L60-67），还可 `complete:true` 整体替换或关闭动态快照。全局误装会与 registry 自身注册冲突 fail loud。

## 6. 自研启示

1. 提示词 = 有序 section 数组 + 变量表 + 工具 schema 注入，全部走统一组装函数。
2. 动态 env 信息用"supersede 快照"追加为 user 消息，而不是反复改 system。
3. 插值缺失抛错是防"空字符串静默污染提示词"的正确姿势。
