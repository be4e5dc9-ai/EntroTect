# DeepSeek Harness 会话存储：事件溯源、持久化后端与恢复

> 归属：`agent-study/deepseek-harness/` | 关键词：SessionEventMap、lossless JSON、seq、ignorable、JSONL、torn tail、fork、end-seed
> 核心文件：`packages/core/session/src/{types,index,surface}.ts`、`packages/session/session-persistence-jsonl/src/index.ts`

---

## 1. 事件溯源日志

全部 13 种会话事件（core/session/src/types.ts:236-337）：

```
turn/start | turn/end | step/start | step/end
user/message
assistant/chunk（原始流增量）| assistant/message（装配结果，引用 chunk 序列）
tool/call | tool/result | tool/code-dispatch-start | tool/code-dispatch（Code Mode 专用）
request/header（请求快照）| request/context（provider/model 变更）
session/end-seed（标记"此之前的日志是种子"）
compaction/start（压缩锁标记）
```

事件信封（types.ts L408-440）：

```ts
type SessionEvent<T> = { type: T; seq: number; time: number;
                         data: SessionEventMap[T];
                         ignorable?: true }
  & (T extends SurfaceEventType
      ? { sourceEventSeqs?: number[]; surfaceOp?: SurfaceOp } : object)
```

### 三条硬纪律

1. **lossless JSON**：append 时单遍递归校验+快照+deepFreeze；BigInt/函数/循环引用在 append 点直接抛错（index.ts:604-655）。脏数据进不了日志。
2. **seq 连续性**：seq = log.length；seed 校验同规则（L512-527）。
3. **ignorable 标记**：读者遇到不认识的必需事件必须拒绝重构而不是跳过（L416-425）——向前兼容的正确姿势。

格式版本 SESSION_FORMAT_VERSION = 0 单调整数。

## 2. Header 与日志分离存储（L61-99）

Header 记录：cwd、parentSession、seedLength（fork 血缘边界）、origin:'subagent'、**delegationDepth（递归预算要能在重启后存活）**、agentPreset。resume 时无需重新推导。

## 3. 持久化后端

抽象缝 `ctx.sessionPersistence`，两个官方实现：

| 后端 | 特性 |
|---|---|
| **JSONL**（session-persistence-jsonl/src/index.ts:121+） | 必填 root（不给 cwd 默认——进程 cwd 会漂移）；packChunks 把连续 assistant/chunk delta 流打包成单行（无损；"体积约减 60%"系【上游注释称】——index.ts L70-76 注释自述，本笔记未独立复测）；zstd 校验帧物理编码；**撕裂尾部恢复** JsonlTornMarker{truncateTo, recoveredEvents}——不完整末帧截断+抢救出的事件（L85-89）；prepared-session 缓存加速 resume |
| SQLite | chunk-row 物理打包；单调 SCHEMA_VERSION |

写入不在 Session.append 热路径上阻塞——持久化插件订阅 session/event 异步缓冲（index.ts:789-791 明示"Persistence is intentionally not implemented here"）；session-checkpoint-policy 在每个模型请求与顶层工具副作用前做语义耐久检查点（base yml L354-356）。

## 4. Resume / Fork / 冷恢复三路径

1. **配置声明**：agent-loop 配 `agents: [{id, resumeSessionId|sessionId, ...}]`（agent-loop/src/index.ts:255-272），构造时 restore-or-create（L355-381：有持久化则尝试恢复既有日志，失败降级新建并上报 agent-loop/config-start-failed）；
2. **Fork**：ctx.sessions.fork(source, boundary?, childId?)（session/index.ts:1081）按 seq 边界切前缀种子出新会话；越界/开 turn 中切被拒（SessionForkErrorCode L771-776 含 OPEN_TURN）；
3. **子代理冷恢复**：continuation manager 从持久化 Session 复活 cold child（见 10-多智能体）。

session/end-seed 事件标记"此之前的日志是种子"，让 resume/replay 区分继承史与本进程产出。

## 5. 自研启示

1. 最小可用 = JSONL append-per-event + 加载时校验 + request/header 快照重建请求。
2. lossless 校验 + deepFreeze 在写入点执行，脏数据零容忍。
3. torn-tail 恢复是崩溃安全的关键一环（最后半行截断而非整文件作废）。
