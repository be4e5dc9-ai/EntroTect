# DeepSeek Harness 上下文管理：五层防线栈

> 归属：`agent-study/deepseek-harness/` | 关键词：token-meter、pruner、spill-policy、compaction-basic、SurfaceOp replace、KV-cache
> 核心文件：`packages/llm/token-meter/`、`packages/spill/spill-policy/`、`packages/compaction/{compaction,compaction-basic}/`、`packages/core/session/src/surface.ts`

---

## 五层防线总览（每层独立可组合）

```
(1) 计量 token-meter → (2) 剪枝 tool-result-pruner → (3) 溢出 spill-policy
    → (4) 压缩 compaction-basic → (5) 表面机制 SurfaceOp replace（支撑第4层的存储语义）
```

## (1) 计量层 token-meter

- `TokenMeter.measure(session, requestHeader?)` **replay-aware**：
  - 优先锚定最近一次真实 provider usage（仅当该调用的 canonical 请求头匹配当前头且总量不低于启发式锚点，L100-115）；
  - 否则对完整 envelope+surface 启发式重估；
- usage 桶互不相交：inputTokens 不含缓存，cacheRead/Write 单列（L43-49）;
- 增量 fold：每个事件只计一次（_sync 尾随）。

## (2) 剪枝层 tool-result-pruner

纯事件门、无服务。base 配置（bundle/base/cordis.patch.yml L360-366）：

```yaml
thresholdChars: 8192   # 超过才剪
headChars: 4096        # 保留头部
tailChars: 1024        # 保留尾部（中间省略号）
```

超阈值的**旧** tool-result 表面节点被重写为 head+省略+tail——replay-safe、无需模型调用。

## (3) 溢出层 spill-policy（模块文档即设计书 index.ts:1-44）

- `maxInlineBytes: 50000`：超限纯文本工具结果全文存入 `ctx.spillStore`（会话私有文件），模型看到 TextRetainer 生成的 head/tail 预览 + 取回路径指引；
- **read 工具豁免**：防 `read→spill→再 read` 死循环；
- **尽力而为**：spill 失败绝不能把成功调用变成 isError（L33-35）；
- 第二条臂：经 tools/code-dispatch-log waterfall 限制 run_code 子调用在日志中的副本体积。

## (4) 压缩层 CompactionEngine 缝 + BasicCompactionEngine

抽象缝三方法（compaction/src/index.ts:96-170）：

| 方法 | 说明 |
|---|---|
| compactIfNeeded(agent, trigger: 'pressure'\|'context-overflow') | 条件触发 |
| compactNow() | 经 agent.runMaintenance() 独占 idle 相位；先写 compaction/start 持久锁标记 |
| compactRegion(start, end) | 按 surface 位置闭区间压缩；两端必须"工具配对平衡"（toolPairingBalancedBefore/After：assistant tool-call 不得与其 result 被拆开）★ |

两个自动触发钩子（compaction-basic）：

```ts
// L147-165 步间压力——挂在 agent/pre-step，请求派生前检查
ctx.on('agent/pre-step', async ({agent, signal}, next) => {
  await this.compactIfNeeded(agent, 'pressure', signal)  // 失败只 warn，继续 turn
  return next()
})
// L179-223 上下文溢出恢复——挂在 agent/request-error
if (failure.code !== CONTEXT_WINDOW_EXCEEDED_CODE || signal.aborted) return next()
const generation = agent.session.surface.replaceGeneration
result = await this.compactIfNeeded(agent, 'context-overflow', signal)
// 只有 pruning/摘要真正推进了 replaceGeneration 才返回 {kind:'retry'}，否则保留原错误
```

阈值策略：`measurement.totalTokens >= contextWindow * thresholdRatio` 触发；目标保留 retainTokens/retainRatio；循环压缩至低于阈值或耗尽 compactionRetries（L304-331）。

★ **KV-cache 感知压缩**：summarizeWithLlm 复用会话自己的 system/tools/前缀消息——"so the provider's KV cache is not invalidated"（L228-230）。压缩本身不破坏前缀缓存。

## (5) 表面机制 SurfaceOp replace ★★★

整个项目最精巧的设计：**日志永远 append-only，但允许"阴影"**。

```
core/session/src/types.ts:376-378
SurfaceOp = { op:'replace', start, end }     // 一个表面事件阴影一段旧表面节点，
                                             // 并在 sourceEventSeqs 引用全部被阴影者

deriveMessages() (core/session/src/index.ts:726-747)
沿有序表面节点折叠派生消息；replace 使 replaceGeneration++ 触发派生缓存整体重建
```

效果：**磁盘无损全史，模型看到压缩视图，UI/审计随时展开原史**。compaction、UI 折叠、未来任何"改历史"需求都变成"新节点阴影旧节点"。

## 自研启示

1. 防线顺序：计量→无模型剪枝→落盘 spill→LLM 摘要，成本递增。
2. 压缩区域必须检查工具配对完整性，否则下次请求 400。
3. 若做事件溯源，一开始就把 surfaceOp/sourceEventSeqs 放进信封——后补代价极高。
